# 인터랙티브 수업 PDF 리더 작업지시서 v1.0

Oct 25, 2026 · @박장정

## 1. 개요

PDF 페이지 사이에 HTML 웹앱을 독립된 페이지로 끼워 넣고, 모든 페이지 위에 S펜으로 판서할 수 있는 태블릿용 수업 리더를 만든다. 가칭은 \*\*레슨덱(LessonDeck)\*\*이다.

- **문제**: 스타노트는 PDF 필기와 메모는 충분하지만 HTML 파일을 넣을 수 없다. 수업 중 형성평가 멀티툴이나 발자국 같은 웹앱을 쓰려면 앱을 전환해야 해서 흐름이 끊긴다.
- **목표**: 한 파일 안에서 PDF 페이지 → HTML 웹앱 페이지 → PDF 페이지로 넘기며 수업한다. 웹앱 위에도 판서할 수 있다.
- **범위 밖(v1)**: 학생 기기 배포, 실시간 공동 편집, 클라우드 동기화.

| 항목 | 가정 |
| --- | --- |
| 기기 | 갤럭시탭 + S펜 (모델 확인 필요) |
| 화면 송출 | 교실 TV·프로젝터로 미러링 또는 HDMI |
| 네트워크 | 교실 와이파이가 불안정할 수 있음 → 오프라인 동작 필수 |
| 사용자 | 교사 1인 |
| 배포 | 웹앱(PWA)으로 Vercel 배포, 태블릿 홈 화면에 설치. 안드로이드 APK(Capacitor)로도 설치 가능 |

## 2. 핵심 개념: 페이지 시퀀스

문서는 PDF 파일 하나가 아니라 **페이지 목록**이다. 각 페이지는 "원본 PDF의 몇 쪽", "HTML 파일", "URL", "빈 페이지" 중 하나를 가리킨다. 삽입·삭제·순서 변경은 목록만 바꾸고 원본 PDF는 건드리지 않는다.

&#91;embedded content: 페이지 시퀀스 예시 · 10쪽 PDF + HTML 1쪽\]

HTML을 "끼워 넣기"(뒤 쪽이 하나씩 밀림)와 "대체하기"(원본 쪽 숨김) 둘 다 지원한다. 숨긴 쪽은 썸네일에서 다시 보이게 할 수 있다. PDF를 여러 개 불러와 한 문서로 잇는 것도 같은 구조로 가능하다.

## 3. 기능 요구사항

MVP는 "PDF 열기 → HTML 페이지 삽입 → 판서 → 저장" 한 바퀴가 태블릿에서 끊김 없이 도는 것까지다.

| ID | 기능 | 세부 내용 | 우선순위 |
| --- | --- | --- | --- |
| F1 | PDF 불러오기 | 기기 파일에서 PDF 선택, 전 페이지를 페이지 목록으로 구성 | MVP |
| F2 | HTML 페이지 삽입 | 원하는 위치(앞/뒤)에 .html 파일 또는 URL을 독립 페이지로 삽입 | MVP |
| F3 | 원본 페이지 숨기기 | HTML로 대체할 PDF 페이지를 삭제 없이 숨김 처리 | MVP |
| F4 | 페이지 재배열 | 썸네일 드래그로 순서 변경, 페이지 복제·삭제 | MVP |
| F5 | 판서 | 펜·형광펜·지우개, 색 3\~5개, 굵기 3단계, 필압 반영 | MVP |
| F6 | HTML 위 판서 | HTML 페이지에서 "조작 모드 ↔ 판서 모드" 전환 | MVP |
| F7 | 빈 페이지 삽입 | 판서용 백지·모눈 페이지 | MVP |
| F8 | 자동 저장 | 편집 즉시 기기 내부(IndexedDB)에 저장, 오프라인 동작 | MVP |
| F9 | 프로젝트 파일 | .lessondeck 파일로 내보내기·불러오기 (PC↔태블릿 이동용) | MVP |
| F10 | 발표 모드 | 툴바 숨김, 좌우 스와이프·이전/다음 버튼으로 넘기기 | MVP |
| F11 | PDF 내보내기 | 필기 포함 PDF 출력, HTML 페이지는 대체 이미지로 출력 | 2차 |
| F12 | 페이지 내 위젯 | PDF 페이지 일부 영역에 HTML을 박스로 삽입 | 2차 |
| F13 | 레이저 포인터 | 잠시 보였다 사라지는 펜 | 2차 |
| F14 | 판서 지우기 단축 | 현재 페이지 필기 전체 지우기, 실행 취소/다시 실행 | MVP |

- HTML 파일은 서버 없이 동작해야 한다. 파일 내용을 프로젝트 안에 저장하고 `srcdoc`으로 렌더링한다.
- URL 삽입은 형성평가 멀티툴처럼 이미 배포된 앱용이다. 인터넷 연결이 필요하다는 표시를 페이지에 띄운다.

## 4. 기술 스택과 아키텍처

서버 없는 단일 웹앱(PWA)으로 만든다. 모든 데이터는 태블릿 안에 저장되고, Vercel은 앱 파일만 배포한다.

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Vite + React + TypeScript | 정적 배포, 빠른 빌드 |
| PDF 렌더링 | pdfjs-dist | 페이지 단위 캔버스 렌더링, 오프라인 동작 |
| 필기 | Pointer Events + perfect-freehand + Canvas 2D | 필압 반영 획, 가벼움 |
| HTML 페이지 | iframe `srcdoc` + `sandbox` | 서버 없이 파일 내용 그대로 실행, 앱 데이터와 격리 |
| 저장 | IndexedDB (idb 라이브러리) | 대용량 PDF·필기 오프라인 저장 |
| 프로젝트 파일 | JSZip | 원본 + manifest + 필기를 한 파일로 |
| PDF 내보내기(2차) | pdf-lib | 원본 PDF에 필기 합성 |
| 설치·오프라인 | vite-plugin-pwa | 홈 화면 설치, 서비스 워커 캐시 |
| 안드로이드 앱 | Capacitor (APK, GitHub Actions 빌드) | 앱 파일을 APK에 내장해 오프라인 실행, 전체 화면·화면 켜짐 유지. R1 대응 시 네이티브 잉크로 확장할 기반 |
| 배포 | GitHub → Vercel | 기존 작업 방식과 동일 |

tldraw 같은 무한 캔버스 대신 **페이지 단위 구조**를 택한다. 요구사항이 "페이지별 편집"이고, 필기 지연을 줄이려면 직접 만든 가벼운 캔버스가 유리하다.

조작 모드에서는 위 세 층에 `pointer-events: none`을 걸어 터치가 iframe으로 내려가게 하고, 판서 모드에서는 다시 켠다.

## 5. 데이터 구조와 저장

원본 PDF는 절대 수정하지 않는다. 문서 = 원본 파일들 + 페이지 순서표(manifest) + 페이지별 필기 데이터로 분리 저장한다.

**manifest.json 예시** (10쪽 PDF의 2쪽 뒤에 HTML 삽입)

```json
{
  "version": 1,
  "title": "동아시아사 3단원 2차시",
  "assets": {
    "pdf-a": { "type": "pdf", "name": "3단원.pdf", "pageCount": 10, "aspects": [0.7071, "…"] },
    "html-quiz": { "type": "html", "name": "퀴즈.html", "warnings": [] },
    "img-map": { "type": "image", "name": "지도.heic", "mime": "image/jpeg", "width": 4032, "height": 3024 },
    "img-stamp": { "type": "image", "name": "참 잘했어요.png", "mime": "image/png", "width": 800, "height": 800 },
    "vid-clip": { "type": "video", "name": "실험.mp4", "mime": "video/mp4", "width": 1920, "height": 1080, "duration": 42.5, "poster": "data:image/jpeg;base64,…" }
  },
  "pages": [
    { "id": "p1", "kind": "pdf", "asset": "pdf-a", "pageIndex": 0 },
    { "id": "p2", "kind": "pdf", "asset": "pdf-a", "pageIndex": 1 },
    { "id": "p3", "kind": "html", "asset": "html-quiz", "aspect": "16:9" },
    { "id": "p4", "kind": "pdf", "asset": "pdf-a", "pageIndex": 2 },
    { "id": "p5", "kind": "url", "url": "https://example.vercel.app", "aspect": "16:9" },
    { "id": "p6", "kind": "blank", "background": "grid",
      "stickers": [
        { "id": "s1", "asset": "img-stamp", "x": 0.55, "y": 0.08, "w": 0.3, "rotation": -8,
          "crop": { "x": 0.1, "y": 0, "w": 0.8, "h": 1 }, "shape": "rounded",
          "border": { "color": "#ffffff", "width": 10 }, "shadow": true, "opacity": 1, "flipX": false }
      ] },
    { "id": "p7", "kind": "youtube", "videoId": "aqz-KE-bpKQ", "start": 90, "aspect": "16:9" },
    { "id": "p8", "kind": "image", "asset": "img-map",
      "boxes": [
        { "id": "b1", "x": 0.06, "y": 0.08, "w": 0.42, "h": 0.06, "text": "임진왜란 전개 보기", "size": 31, "color": "#1565c0", "link": { "type": "page", "pageId": "p3" } },
        { "id": "b2", "x": 0.06, "y": 0.9, "text": "", "size": 22, "color": "#1a1a1a", "link": { "type": "url", "url": "https://encykorea.aks.ac.kr/" } }
      ] },
    { "id": "p9", "kind": "video", "asset": "vid-clip" }
  ],
  "hidden": []
}
```

- **원본(assets)**: 원본 파일 자체는 manifest 밖에 따로 보관하고(아래 "저장"), manifest에는 종류와 화면에 필요한 정보만 둔다. `pdf`는 쪽수와 쪽마다의 가로÷세로 비율(`aspects`), `html`은 CDN 사용 등 경고(`warnings`), `image`·`video`는 저장한 형식(`mime`)과 픽셀 크기, 동영상은 길이(`duration`, 초)와 첫 화면 축소 이미지(`poster`)를 가진다.
- **페이지 종류**: `pdf`(원본 PDF의 특정 쪽), `html`(내장 HTML 파일), `url`(외부 웹앱), `youtube`(유튜브 동영상), `image`(그림 한 장), `video`(기기에 저장된 동영상), `blank`(백지·모눈).
  - `image` 페이지는 그림의 가로÷세로 비율 그대로 페이지가 된다. PNG·JPEG·WebP·GIF·SVG·BMP·AVIF·ICO는 그대로 보관하고, 브라우저가 못 그리는 HEIC/HEIF(갤럭시·아이폰 사진)는 JPEG으로, TIFF(스캔)는 PNG로 바꿔 보관한다. 긴 변이 4096px을 넘는 사진은 4096px로 줄인다(SVG·GIF 제외).
  - `video` 페이지는 동영상의 비율 그대로 페이지가 되고 `<video controls playsinline>`로 페이지 안에서 재생한다. 조작/판서 모드가 있는 인터랙티브 페이지이며, 다른 페이지로 넘어가면 일시정지한다. 원본 파일을 그대로 보관한다(인터넷 불필요).
  - `youtube` 페이지는 `videoId`(11자), 재생목록이면 `list`, 시작 시각이면 `start`(초)를 가진다. 일반·짧은(youtu.be)·Shorts·재생목록 링크를 모두 이 형태로 바꿔 `youtube-nocookie.com/embed`로 페이지 안에서 바로 재생한다(유튜브 시청 페이지는 다른 앱 안에 띄울 수 없음). 다른 페이지로 넘어가면 일시정지하고, 영상 주인이 삽입을 막았으면 "YouTube에서 열기"로 안내한다. 인터넷이 필요하다.
  - `blank` 페이지는 `background`(`"plain"` 백지 · `"grid"` 모눈)와 `aspect`(가로÷세로 숫자)를 가진다. 추가할 때 바로 앞 페이지와 같은 비율로 만든다. 예: `{ "id": "p6", "kind": "blank", "background": "grid", "aspect": 0.7071 }`
  - `html`·`url`·`youtube` 페이지의 `aspect`는 `"16:9"`·`"4:3"`·`"A4"` 중 하나다(R8). 웹앱은 각각 1280×720 · 1024×768 · 794×1123 크기의 화면으로 그린 뒤 페이지 크기에 맞춰 축소·확대한다. 기본값은 `"16:9"`.
  - `hidden`: 숨긴 페이지 id 목록(F3). 숨긴 페이지는 넘길 때 건너뛰고, 페이지 바에서는 흐리게 보이며 다시 보이게 할 수 있다.
  - HTML 원본(`assets`의 `type: "html"`)은 파일 내용을 그대로 보관하고 `<iframe srcdoc sandbox="allow-scripts allow-forms allow-popups allow-modals">`로 실행한다(`allow-same-origin` 금지, R5). URL 페이지는 그 사이트 자신의 출처로 열리도록 `allow-same-origin`을 더한다(R6). 단, 레슨덱과 같은 출처의 주소면 빼서 격리를 유지한다.
  - **URL 페이지가 하얗게 남지 않게** (v0.11): `allow-popups-to-escape-sandbox`·`allow-downloads`·`allow-presentation`·`allow-storage-access-by-user-activation`을 더 허용하고(앱 화면을 바꾸는 top 이동은 계속 금지), Referer는 `strict-origin-when-cross-origin`(삽입 허용 사이트를 확인하는 서비스 대비). 구글 슬라이드·문서·시트·설문·드라이브, 캔바 주소는 화면에 띄울 때만 삽입용 주소(`/embed`, `/preview`, `embedded=true`, `?embed`)로 바꾸고 저장된 주소와 "브라우저에서 열기"는 원래 주소를 쓴다.
  - **구글 지도** (v0.17): 지도 주소(`google.*/maps/…`, `maps.google.*`)는 "다른 앱 안에 띄우지 마세요"라 iframe에서 `ERR_BLOCKED_BY_RESPONSE`로 막힌다 → 띄울 때만 API 키가 필요 없는 삽입용 지도 `https://maps.google.com/maps?…&output=embed`로 바꾼다. 장소(`/maps/place/이름/…!3d위도!4d경도`) → `q=이름&ll=장소 좌표`, 검색(`/maps/search/`) → `q`, 길찾기(`/maps/dir/A/B`) → `saddr`·`daddr`, 지도 위치(`/@위도,경도,확대z`) → `ll`·`z`(높이 `…m`·`!1e3`는 위성 `t=k`), `?q=`·`?api=1` 주소도 알아본다. "지도 퍼가기"(`/maps/embed?pb=`) 주소와, 웹 주소 칸에 붙여 넣은 `<iframe src="…">` 코드(그 `src`만 씀)는 그대로 쓴다. 이렇게 만든 삽입용 지도는 앱이 대신 받아 오지 않는다(FrameProxy 목록에서 뺌).
  - **짧은 지도 공유 주소** (v0.17): 지도 앱의 "공유"는 `maps.app.goo.gl/…`(또는 `goo.gl/maps/…`)를 준다. 다른 사이트의 넘겨주기는 웹 화면이 볼 수 없으므로 안드로이드 앱이 열어 보고(`WebFrames.resolve`, 넘겨주기를 최대 6번 따라감, 넘겨주기 대신 안내 페이지면 그 안의 지도 주소) 실제 주소를 기기에 기억(`localStorage lessondeck.resolvedLinks`, 최근 200개)한 뒤 위 삽입용 지도로 띄운다. 알아내는 동안은 iframe을 만들지 않는다. 저장된 페이지 주소와 "브라우저에서 열기"는 선생님이 넣은 짧은 주소 그대로. 브라우저(웹 버전)는 알아낼 수 없어 막히는 iframe 대신 안내("지도 퍼가기" 코드나 전체 주소를 넣기)와 다시 시도·브라우저에서 열기·그래도 보기를 보여 준다.
  - 불러오는 동안 안내(0.5초 뒤 표시, 4초 뒤에는 사이트를 가리지 않는 위쪽 띠), 15초가 지나도 안 열리면 원인 안내와 "다시 시도·브라우저에서 열기·그래도 보기", 오프라인이면 안내 후 다시 연결될 때 저절로 다시 불러온다. 오른쪽 위에는 늘 "브라우저에서 열기".
  - 안드로이드 앱(네이티브): ① iframe 안의 이동(링크, 사이트가 보낸 이동)은 그 iframe 안에서 한다 — Capacitor 기본은 앱 밖 주소면 무조건 바깥 브라우저로 보내고 이동을 취소해 iframe이 하얗게 남았다. ② 제3자 쿠키 허용(로그인·세션이 필요한 사이트), http 사이트·https 안의 http 자원 허용(`allowMixedContent`). ③ "다른 앱 안에 띄우지 마세요" 머리글(`X-Frame-Options`, CSP `frame-ancestors`)이 있는 사이트는, 이 문서의 URL 페이지 사이트(와 그 사이트가 보낸 이동 대상)에 한해 GET 문서 요청을 앱이 대신 받아 그 머리글만 빼고 보여 준다(`FrameProxy.java`, 쿠키는 웹뷰와 공유). ④ iframe 문서가 실패하면(연결 실패, 401/403/404/5xx 등) 이유를 화면 안내로 알린다.
- **텍스트 상자·하이퍼링크(`boxes`)**: 어느 종류의 페이지든 `boxes` 배열을 가질 수 있다(없으면 빈 것). 상자 하나는 `{id, x, y, w?, h?, text, size, color, bg?, border?, font?, bold?, italic?, underline?, align?, anim?, veil?, link?, role?, backOf?}`.
  - `x`·`y`는 상자 왼쪽 위의 페이지 대비 0\~1 위치, `size`는 글자 크기(필기 굵기와 같은 "페이지 가로 = 1000" 단위), `text`는 줄바꿈 포함 글자.
  - `w`·`h`(상자 크기, 페이지 가로·세로 대비 0\~1)가 **없으면** 글자 크기 `size` 그대로 글 길이만큼 넓어지고(페이지 오른쪽 끝에서 줄바꿈), **있으면** 그 상자 안에 글이 꽉 차도록 글자 크기를 자동으로 정한다(상자 폭에서 줄바꿈, 줄 높이 1.3). 상자 손잡이로 크기를 바꾸면 `w`·`h`가 생기고, 그때 정해진 글자 크기를 `size`에도 적어 둔다(이전 버전 호환·썸네일).
  - `bg` (v0.19, 배경색): 없으면 배경 없음(0.18까지 만든 상자), `"auto"`면 글자색에 맞춰 잘 보이는 배경을 그때그때 고른다(글자색을 바꾸면 따라 바뀜), `"#rrggbb"`면 그 색. 새로 만드는 글상자는 `"auto"`. 링크 상자는 쓰지 않는다(링크 단추 모양). 배경이 있으면 글자 둘레에 여백(가로 0.3em·세로 0.1em)을 두고 모서리를 둥글게 그린다.
  - `border` (v0.20, 테두리): `{color, w}`. `color`는 `"auto"`(글자색을 따라감) 또는 `"#rrggbb"`, `w`는 굵기 단계 1·2·3(글자 크기의 0.05·0.09·0.14배). 없으면 테두리 없음. 링크 상자는 쓰지 않는다. 테두리가 있으면 배경처럼 글자 둘레 여백·둥근 모서리, 상자 안쪽에 그려 상자 크기는 그대로.
  - **서식 (v0.25)**: 상자 전체에 적용한다(글자 하나하나 따로가 아님). 없으면 0.24까지와 같은 모양.
    - `font`: 글꼴 — 없으면 기본(고딕, 기기 글꼴), `"serif"` 명조(나눔명조), `"hand"` 손글씨(연성), `"round"` 둥근(주아), `"title"` 제목(검은고딕). 기본 말고는 앱에 넣은 글꼴(SIL OFL, `@fontsource`)이라 인터넷 없이도 기기마다 같다.
    - `bold: true` 굵게 · `italic: true` 기울임 · `underline: true` 밑줄. 없으면 끔.
    - `align`: 줄 맞춤 — 없으면 왼쪽, `"center"` 가운데, `"right"` 오른쪽. 크기가 정해진 상자(`w`·`h`)는 상자 폭 안에서, 아니면 가장 긴 줄 폭 안에서 맞춘다.
    - 글자 너비는 그 상자의 글꼴·굵기·기울임으로 재므로 줄바꿈·크기 맞춤·썸네일이 화면과 같다. 0.24까지의 앱은 이 값들을 몰라 기본 글꼴·왼쪽 맞춤으로 그린다(크기가 정해진 상자는 글자 크기를 다시 맞춤).
  - **애니메이션 (v0.26, 쪽지·강조 v0.28)** `anim: {reveal?: "fold", typing?: true, note?: {w?, color?, label?}, emphasis?}`: 강의 모드에서 상자가 어떻게 나타나고 강조되는지. 값이 하나도 없으면 `anim`을 뺀다.
    - `reveal: "fold"` 접었다 펼치기 — 강의 모드에서는 상자 왼쪽 위에 붙은 작은 **쪽지(포스트잇)**로 보이다가 누르면 쪽지가 떼어지며 상자가 펼쳐진다(0.26의 두루마리 띠는 0.28에서 쪽지로 바뀜, 데이터는 같음).
      - `note.w`: 쪽지 한 변(페이지 가로 대비, 0.03~0.15, 없으면 0.05). `note.color`: 쪽지 색 `"#rrggbb"`(없으면 노랑). `note.label`: 쪽지에 손글씨로 쓰인 짧은 글(8자까지, 없으면 "?").
    - `typing: true`: 펼친 뒤 글자가 한 자씩 입력되듯 나온다(한글은 ㅇ → 오 → 와 → 왕처럼 자모가 조합되며). 없으면 펼칠 때 글자도 함께 보인다.
    - `emphasis` 강조 (v0.28): `"highlight"` 형광펜(글 아래에 형광펜이 쓱 칠해지고 남음, 다시 누르면 지워짐) · `"bounce"` 통통(상자가 통통 튐) · `"glow"` 반짝(빛이 돌고 반짝임). 강의 모드에서 손가락(마우스)으로 상자를 톡 누르면, 그리고 접힌 상자를 펼쳐 다 쓴 뒤 한 번.
    - 강의 모드가 아니면(평소 보기·텍스트 모드·썸네일·표지 그림) 늘 펼친 그대로·강조 없이 그린다. 펼쳤는지·형광펜을 칠했는지는 저장하지 않는다(강의 모드를 시작할 때마다 처음으로). 링크 상자는 쓰지 않는다(누르면 링크로 가야 하므로). 0.25까지의 앱은 이 값을 몰라 늘 펼친 상자로 그리고, 0.26·0.27은 `reveal`이 없는 강조만 있는 값을 모른다(그냥 상자).
  - **베일 (v0.28)** `veil: {color}`: 이 상자는 글상자가 아니라 **가리는 천**이다. 강의 모드에서 상자 자리(`x`·`y`·`w`·`h`, 늘 크기가 정해져 있음)를 `color` 천으로 덮어 그 밑(PDF에 인쇄된 정답, 다른 글상자·그림·필기)을 가리고, 누르면 베일이 걷히며 드러난다. `text`는 베일 위에 보이는 짧은 글(없으면 "?"), `size`·글자색은 쓰지 않는다. 강의 모드가 아니면 반투명(그 밑이 보임)·점선 테두리로 그린다(썸네일도). 걷었는지는 저장하지 않는다. 0.27까지의 앱은 `veil`을 몰라 보통 글상자(글 "?" 등)로 그린다.
  - 줄바꿈 규칙(화면·썸네일 공통): 띄어쓰기 단위로 나누고, 한 단어가 상자보다 길면 글자 단위로 나눈다. 글자 너비는 앱 글꼴(Pretendard 등)로 잰다.
  - `link`: `{type: "page", pageId}`(이 문서의 다른 페이지로 이동) 또는 `{type: "url", url}`(외부 웹 주소, http/https만). 링크가 있는 상자를 누르면 이동한다(텍스트 모드에서는 편집).
  - `text`가 빈 페이지 링크는 화면에서 **링크 아이콘 + "3P" + 화살표 아이콘**으로 그때의 쪽 번호를 보여 준다(페이지 순서를 바꿔도 맞음, 숨긴 쪽이면 "숨김", v0.15 — 전에는 "3쪽으로 가기 →"). 글자로만 뜻을 전해야 할 때(링크를 풀고 글자만 남김, 시스템 클립보드, PC 마우스를 올렸을 때 안내)는 "3쪽으로 가기 →"·"↩ 3쪽으로 돌아가기"를 쓴다. 웹 주소 링크는 주소의 사이트 이름을 보여 준다.
  - **돌아가기 링크(자동)**: 페이지 A의 상자에 페이지 B로 가는 링크를 걸면, B에 A로 돌아가는 상자를 자동으로 만든다: `role: "back"`, `backOf: <A의 링크 상자 id>`, `text: ""`(화면에는 링크 아이콘 + "NP" + ↩ 아이콘), B의 오른쪽 위부터 차례로 놓는다. B에 이미 A로 가는 링크가 있으면 새로 만들지 않는다. 원래 링크를 지우거나 다른 곳으로 바꾸면 `backOf`가 그 상자인 돌아가기 링크도 지우거나 옮긴다.
  - 연결한 페이지가 삭제되면: 돌아가기 링크는 숨기고(페이지 삭제를 되돌리면 다시 보임), 사용자가 만든 링크는 "연결된 페이지 없음"으로 흐리게 보인다.
  - 페이지를 복제하면 상자도 새 id로 복사한다. 복사한 돌아가기 링크는 `backOf`를 떼어 보통 링크가 된다.
- **상자 화살표(`arrows`, v0.20 · 아무 곳 가리키기·휘기 v0.24)**: 어느 종류의 페이지든 `arrows` 배열을 가질 수 있다(없으면 빈 것). 하나는 `{id, from, to?, at?, bend?, color, both?}` — `from`은 같은 페이지의 상자 id(화살표가 나오는 상자), 끝은 둘 중 하나: `to`(이어진 상자 id) 또는 `at`(v0.24, 화살 끝이 가리키는 곳 `[x, y]`, 상자 `x`·`y`와 같은 페이지 대비 0\~1 비율 — 밑줄 그은 곳·그림 등 아무 곳). `bend`(v0.24): 휜 정도 = 곡선 가운데가 곧은 선 가운데에서 비켜난 거리 ÷ 곧은 선 길이, `+`는 가는 방향의 오른쪽(화면 기준), 없거나 0이면 곧은 선(-0.8\~0.8). `color`는 선 색, `both: true`면 양쪽 화살표.
  - 그리기: 시작 상자 가운데 → 끝(상자 가운데 또는 `at`)을 잇는 2차 베지어 곡선(조절점 = 곧은 선 가운데에서 `bend × 길이 × 2`만큼 옆, 곧으면 직선)을 시작 상자 테두리(+조금 띄움)에서 자르고, 끝이 상자면 그 테두리 앞에서, `at`이면 그 점에 화살촉 끝이 닿게 한다. 촉은 곡선이 끝나는 방향으로(양쪽이면 시작에도). 굵기는 페이지 가로 1000 기준 3, 상자를 옮기거나 크기를 바꾸면 따라간다(끄는 중에도). 끝이 시작 상자 안이면 그리지 않는다. 화면·썸네일 공통(`doc/arrows.ts`).
  - `to`·`at`이 둘 다 없거나 상자가 없으면 그리지 않는다. 0.23까지의 앱은 `at` 화살표를 그리지 않고(끝 상자가 없음), `bend`는 무시해 곧게 그린다.
  - 상자를 지우면 그 상자에 닿은 화살표도 지운다. 같은 두 상자 사이 같은 방향 화살표는 하나만. 페이지 복제·페이지 붙여넣기는 새 상자 id로 바꿔 함께 복사한다(한쪽 상자가 없으면 버림). 상자만 복사·붙여넣기할 때는 화살표를 가져가지 않는다.
  - **복사·잘라내기·붙여넣기**: 앱 안 클립보드(문서를 바꿔도 남고 앱을 끄면 사라짐)에 상자를 담는다. 붙이면 새 id로 같은 자리(이미 상자가 있으면 조금씩 비켜서)에 놓는다. 페이지 링크는 같은 문서에 그 페이지가 있으면 그대로 잇고, 위 규칙대로 붙인 페이지로 돌아가는 링크도 만든다(돌아가기 링크를 붙인 경우는 제외). 다른 문서에 붙인 페이지 링크는 링크를 풀고 보이던 글자("3쪽으로 가기 →" 등)만 남긴다. 잘라내기는 복사 + 지우기(돌아가기 링크도 지움)라서, 다른 페이지에 붙이면 링크와 돌아가기 링크가 새 자리로 옮겨 간 것과 같다. 시스템 클립보드에는 보이는 글자를 넣고, 다른 앱에서 복사한 글을 붙이면 새 글상자(웹 주소 하나면 웹 주소 링크)가 된다.
- **이미지 스티커(`stickers`, v0.14)**: 어느 종류의 페이지든 그림을 페이지 위에 자유롭게 붙일 수 있다(그림 한 장이 페이지가 되는 `image` 페이지와 다름). 상자 하나는 `{id, asset, x, y, w, rotation?, crop?, shape?, border?, shadow?, opacity?, flipX?, flipY?, popup?}`. 배열 순서가 쌓인 순서(뒤가 위).
  - `asset`: 이 문서의 `image` 원본 id (이미지 페이지와 같은 보관 규칙. 스티커는 긴 변 2048px까지 줄인다).
  - `x`·`y`: 돌리기 전 스티커 틀의 왼쪽 위(페이지 대비 0\~1), `w`: 틀 폭(페이지 가로 대비). 높이는 따로 두지 않고 "보이는 부분의 그림 비율"로 정해 그림이 찌그러지지 않는다: 높이(px) = 폭(px) × (crop.h × 그림 세로) ÷ (crop.w × 그림 가로).
  - `rotation`: 틀 가운데를 축으로 시계 방향 각도(도, 기본 0). `crop`: 그림에서 보일 부분 `{x, y, w, h}`(그림 대비 0\~1, 없으면 전체).
  - 꾸미기: `shape` `"rect"`(기본)·`"rounded"`(둥근 모서리)·`"circle"`(틀에 맞는 원·타원), `border` `{color, width}`(테두리, 굵기는 "페이지 가로 = 1000" 단위, 흰 굵은 테두리 = 스티커 모양), `shadow`(그림자), `opacity`(0.2\~1, 기본 1), `flipX`·`flipY`(뒤집기).
  - **팝업 그림 (v0.27)** `popup: {w}`: 페이지에는 작은 **아이콘**으로 보이고, 누르면 그 페이지 위에 크게 뜬다(그림 바깥이나 ✕를 누르면 다시 작아짐).
    - 아이콘은 정사각형, 폭 `popup.w`(페이지 가로 대비, 0.03~0.5, 처음 0.07), 자리 `x`·`y` = 아이콘 왼쪽 위, `rotation`도 아이콘에. 그림은 보이는 부분(`crop`)의 가운데 정사각형만 꽉 채워 보이고, 모양은 `shape`(없으면 둥근 모서리), 테두리는 `border`(없으면 흰 테두리 4), 그림자는 늘. 썸네일·표지·고르기(누른 자리의 스티커)도 이 아이콘 모양으로.
    - `w`·`crop`·뒤집기는 크게 볼 때와 팝업을 껐을 때의 원래 스티커 값으로 그대로 둔다. 팝업을 켜고 끌 때 아이콘·스티커 가운데를 같은 자리에 맞춘다(끄면 원래 크기로 돌아감).
    - 크게 볼 때: 보이는 부분(`crop`, 뒤집기)을 원래 비율 그대로 페이지 가로 92%·세로 88% 안에 가장 크게, 페이지 가운데. 돌리기·모양·테두리·투명도는 쓰지 않는다.
    - 0.26까지의 앱은 `popup`을 몰라 `x`·`y` 자리에 원래 크기 스티커로 그린다.
  - 층 순서: 페이지(PDF·그림·웹) → **스티커** → 형광펜(v0.23) → 펜 필기 → 글상자. 스티커 위에 판서할 수 있고, 평소에는 누름이 스티커를 지나간다(웹 페이지 조작 포함). 스티커는 길게 누르기 메뉴나 텍스트 모드에서 눌러 골라 고친다.
  - 페이지를 복제하면 스티커도 새 id로 복사한다(원본 그림은 같이 씀).
- **앱 안 클립보드 (v0.14)**: 마지막으로 복사·잘라낸 것 하나(글상자 / 스티커 / 페이지)를 담는다. 문서를 바꿔도 남고 앱을 끄면 사라진다. 다른 문서에 붙일 수 있도록 스티커·페이지는 쓰는 원본 파일(Blob)도 함께 담는다.
  - 스티커 붙이기: 새 id로 같은 자리(겹치면 조금 비켜서), 길게 누른 자리면 그 자리에. 다른 문서면 원본 그림을 그 문서에 넣는다.
  - **페이지 복사·잘라내기·붙여넣기**: 페이지 + 그 페이지 필기 + 글상자·스티커 + 쓰는 원본을 담는다. 붙이면 새 페이지 id로 들어가고(보이는 상태), 필기도 새 페이지에 복사한다. 잘라내기는 복사 + 삭제(알림의 "되돌리기"로 복구).
    - 같은 문서: 원본을 그대로 같이 쓴다. 다른 문서: 원본을 그 문서에 넣는다. PDF 쪽은 담은 쪽만 뽑은 새 PDF(pdf-lib, 원래 벡터 그대로)로 넣어 큰 PDF 전체가 복사되지 않게 한다(뽑지 못하면 PDF 전체). 원본 id가 겹치면 같은 파일(종류·이름·크기 같음)일 때만 같이 쓰고, 아니면 새 id로 바꿔 넣는다.
    - 글상자의 페이지 링크: 같은 문서에 그 페이지가 있으면 그대로, 다른 문서면 보이던 글자만 남긴다(글상자 붙여넣기와 같음). 돌아가기 링크는 `backOf`를 떼어 보통 링크가 된다.
- **다른 앱에서 복사한 것 붙여넣기 (v0.15)**: 기기(시스템) 클립보드의 그림·링크·글도 붙인다. 앱 안 클립보드와 둘 중 **나중에 복사한 쪽**을 붙인다: 앱 안 클립보드에 담은 뒤 앱을 떠났거나(다른 앱·분할 화면으로 포커스가 감) 앱 안 입력칸에서 글을 복사했으면 시스템 클립보드를 먼저 읽고, 비어 있거나 읽을 수 없으면 앱 안 클립보드를 쓴다.
  - **페이지 안에 붙이기**(길게 누르기 메뉴 "여기에 붙여넣기", 도구 막대 붙여넣기, PC Ctrl+V): 그림 → 이미지 스티커(누른 자리), 웹 주소 하나 → 웹 주소 링크 글상자, 그 밖의 글 → 글상자.
  - **페이지 바에서 붙이기**(+ 메뉴 "붙여넣기", 페이지 ⋯ 메뉴 "앞/뒤에 붙여넣기"): 새 페이지가 된다. 그림 → 이미지 페이지, 유튜브 링크 → 유튜브 페이지, 웹 주소 → 웹 주소 페이지, 글 → 빈 페이지(옆 페이지와 같은 비율) 위 글상자. 앱 안에서 복사한 페이지는 그 페이지들, 글상자·스티커는 그것을 담은 빈 페이지.
  - 읽는 방법: 안드로이드 앱은 네이티브(`SystemClipboard.read`)로 첫 항목을 읽는다 — 그림 content URI면 바이트(25MB까지)와 형식, 아니면 글(웹 주소 URI는 주소 글). 웹 버전은 `navigator.clipboard.read()`(브라우저가 권한을 물음), 막히면 Ctrl+V 안내. Ctrl+V의 paste 이벤트는 그 자리의 클립보드 내용을 바로 쓴다.
- **필기 데이터**: 페이지 id별로 저장한다. 획마다 `{tool, color, width, points:[x, y, pressure]}`. 좌표는 페이지 크기 대비 0\~1 비율로 저장해 화면 크기가 바뀌어도 위치가 유지되게 한다.
  - `width`는 "페이지 가로 = 1000" 기준 단위다(예: 2 → 페이지 가로의 0.2%). 좌표와 마찬가지로 화면 크기와 무관하게 굵기 비율이 유지된다. 마우스·손가락 획은 실제 필압이 없으므로 `simulatePressure: true`를 함께 저장한다.
  - **도형 획 (v0.18)**: 도형(직선·화살표·원·사각형 등)은 같은 획 배열에 `shape`를 더한 획으로 저장한다 — `{id, tool, color, width, points, shape: {kind, cx, cy, w, h, rot, pts?, curve?}}`. 실행 취소·지우개·동기화·내보내기·페이지 복사·썸네일이 획과 똑같이 동작한다.
    - `kind`: `line`(선) · `arrow`(화살표) · `arrow2`(양쪽 화살표) · `ellipse`(원·타원) · `rect`(사각형) · `roundrect`(둥근 사각형) · `triangle`(이등변삼각형) · `rtriangle`(직각삼각형) · `diamond`(마름모) · `pentagon`(오각형) · `hexagon`(육각형) · `star`(별) · `heart`(하트) · `polygon`(그린 대로의 다각형).
    - `cx`·`cy`: 중심, 점과 같은 0\~1 비율 좌표. `w`·`h`: 크기, 둘 다 **페이지 가로 대비 비율**(페이지 비율과 상관없이 모양이 그대로). 선·화살표는 `w` = 길이, `h` = 0. `rot`: 시계 방향 회전(도). `pts`: `polygon`의 꼭짓점, `w×h` 상자 안의 -0.5\~0.5 좌표.
    - `curve` (v0.24, `line`·`arrow`·`arrow2`만): 곡선 = 3차 베지어의 두 조절점 `[u1, v1, u2, v2]`. 두 끝을 잇는 곧은 선을 x축(시작 -0.5, 끝 +0.5), 그 길이를 1로 본 좌표(회전·크기는 `rot`·`w`를 따름, `v`가 +면 화면에서 `rot` 방향의 오른쪽). 없으면 곧은 선. 화살촉은 곡선이 끝나는 방향으로. 끝점을 옮기거나 돌려도 곡선 모양(비율)은 그대로. 0.23까지의 앱은 `curve`를 몰라 곧게 그린다(`points`에는 곡선 꼭짓점).
    - 그리기는 `shape`에서 다시 만든 선(고른 굵기, 둥근 이음)으로 하고, `points`에는 그 선의 꼭짓점을 넣어 둔다(`shape`를 모르는 옛 버전도 비슷하게 그림).
- **HTML 페이지 필기**: HTML 내부 스크롤과 무관하게 페이지 프레임 기준으로 고정한다(판서는 칠판처럼 화면에 남는다).
- **자동 저장**: IndexedDB(`lessondeck` DB). 획이 끝날 때마다 해당 페이지만 저장하고, 페이지 구성·제목이 바뀌면 0.4초 뒤 manifest를 저장한다. 다시 켜면 마지막에 보던 문서를 연다.
  - `docs`: 문서마다 `{id, title, createdAt, updatedAt, pageCount, manifest, thumb, thumbPage}`. `updatedAt`은 내용(페이지·필기·제목)이 바뀐 시각이며 동기화의 기준이다. `thumb`은 홈 카드에 쓰는 썸네일 페이지 그림(JPEG data URL, 폭 480px, 페이지 + 스티커 + 필기 + 글상자), `thumbPage`는 그 그림이 어느 페이지인지(v0.22). 기기마다 만들고 동기화하지 않는다.
  - `assets`: `[docId, assetId]` → 원본 Blob. `ink`: `[docId, pageId]` → 획 배열.
  - `sync`: 문서별 드라이브 동기화 상태 `{docFileId, remoteUpdatedAt, syncedLocalUpdatedAt, assetFiles}`. `tombstones`: 이 기기에서 지운 문서(다음 동기화 때 드라이브에서도 지움). `meta`: 마지막 문서, 드라이브 연결 정보, 폴더 정리(`library`, 아래), 웹 주소 페이지 미리보기 그림.
  - 시작할 때 `navigator.storage.persist()`로 저장소가 지워지지 않게 요청한다.
- **프로젝트 파일(.lessondeck)**: 위 구조를 그대로 zip으로 묶는다. `manifest.json`(위 manifest + `format: "lessondeck"`, `createdAt`, `updatedAt`, 원본 경로표 `files: {assetId: "assets/<assetId>.<확장자>"}`), `ink/<pageId>.json`, `assets/`. 홈의 "파일 가져오기"로 열면 새 문서가 된다.
- **폴더(문서 정리, v0.13)**: 홈의 문서를 폴더로 정리한다(폴더 안에 폴더 가능). 문서 내용과 따로 `meta`의 `library` 한 건에 둔다 — 문서를 옮기거나 폴더 이름을 바꿔도 문서 `updatedAt`이 바뀌지 않으므로 문서 동기화·충돌 사본과 무관하다.

  ```json
  {
    "version": 1,
    "folders": {
      "f-1": { "id": "f-1", "name": "동아시아사", "parentId": null, "color": "#1c7ed6", "createdAt": 1761500000000, "updatedAt": 1761500000000 },
      "f-2": { "id": "f-2", "name": "3단원", "parentId": "f-1", "createdAt": 1761500000000, "updatedAt": 1761600000000, "deleted": true }
    },
    "placements": {
      "doc-123": { "folderId": "f-1", "updatedAt": 1761600000000 }
    },
    "covers": {
      "doc-123": { "cover": "#24497a", "page": "p-7", "updatedAt": 1762700000000 }
    }
  }
  ```

  - `parentId: null`은 맨 위("내 문서"). 문서가 `placements`에 없거나 `folderId: null`이면 맨 위. `color`는 폴더 아이콘 색(없으면 기본색).
  - 지운 폴더는 `deleted: true`로 남겨 다른 기기에 "지웠음"을 전한다. `updatedAt`은 폴더·배치 하나하나가 바뀐 시각이다.
  - 화면에 보일 위치: 문서의 폴더나 폴더의 부모가 지워졌거나 없으면 살아 있는 가장 가까운 윗 폴더(없으면 맨 위)에 보인다. 두 기기에서 동시에 옮겨 서로가 서로의 안에 든 고리가 생기면 그 폴더들을 맨 위에 보인다.
  - 폴더 지우기: "폴더만 지우기"는 안의 문서·폴더를 지운 폴더의 부모로 꺼내고, "안의 문서까지 모두 삭제"는 하위 폴더를 모두 지우고 그 안의 문서를 삭제한다(문서 삭제 규칙 그대로, 드라이브 사본도 삭제).
  - **표지 (`covers`, v0.21)**: 홈 문서 카드의 표지. `cover`는 `"auto"`(문서 id로 정한 표지 색), `"#rrggbb"`(고른 표지 색), `"page"`(표지 대신 썸네일 페이지 그림을 통째로 — 이 기기에 `thumb`가 없으면 자동 표지로 보임). `page`(v0.22)는 "썸네일로 고르기"로 고른 페이지 id: 표지 아래쪽 절반에 그 페이지 그림이 꽂혀 보인다. 없으면 표지만(그림을 통째로 쓸 때는 첫 페이지). 이 기기의 `thumbPage`가 `page`와 다르면(다른 기기에서 고름) 홈이 그 문서를 열어 그림을 새로 만든다. 고른 페이지를 지웠으면 꽂힌 그림 없이 표지만. 문서가 `covers`에 없으면 `"auto"`. 자동으로 돌려도 `"auto"`로 남겨 다른 기기에 전한다. 배치처럼 문서마다 `updatedAt`이 큰 쪽을 고르고(같으면 글자 순), 표지를 바꿔도 문서 `updatedAt`은 그대로다. `covers`가 비었으면 키에서 빼 0.20까지의 정리와 같은 값으로 비교한다(`page`도 있을 때만 키에 넣는다). 0.20까지의 앱은 `covers`를 모르므로 합칠 때 버리지만, 새 앱이 다시 합치면 이 기기 것이 살아 있어 다시 올린다.
  - 새 문서(PDF·빈 노트·가져오기·샘플)는 홈에서 보고 있던 폴더에 만든다. 동기화 충돌로 생긴 "(다른 기기)" 사본은 원래 문서와 같은 폴더에 둔다. 프로젝트 파일(.lessondeck)에는 폴더·표지를 넣지 않는다.
- **구글 드라이브 백업·동기화**: 구글 계정의 앱 전용 숨김 폴더(`appDataFolder`, 권한 `drive.appdata`)에 문서마다 두 종류의 파일을 둔다. 사용자의 드라이브 파일은 보지도 건드리지도 않는다.
  - `doc-<docId>.json.gz`: `{format: "lessondeck-sync", version: 1, docId, createdAt, updatedAt, manifest, ink: {pageId: 획[]}}`를 gzip. 파일 속성(appProperties) `{kind: "doc", docId, updatedAt}`.
  - `asset-<docId>-<assetId>`: 원본 파일 그대로, 한 번만 올린다. 속성 `{kind: "asset", docId, assetId}`. 5MB보다 크면 이어 올리기(resumable)로 보낸다.
  - `library.json.gz`: 위 폴더 정리(`library`)를 gzip. 속성 `{kind: "library", updatedAt}`. 계정에 하나만 둔다. 합치기는 폴더·배치·표지마다 `updatedAt`이 큰 쪽을 고르고(같으면 지운 쪽, 그래도 같으면 내용을 글자 순으로 비교해 어느 기기에서 합쳐도 같은 결과), 그래서 두 기기에서 따로 정리해도 충돌 사본 없이 모두 반영된다. 동기화 때마다 드라이브 `updatedAt`이 마지막으로 맞춘 값과 다르면 받아 합치고, 합친 결과가 드라이브 것과 다르면 올린다(맞춘 상태는 `meta`의 `librarySync`). 파일이 둘 이상이면(두 기기가 처음에 동시에 만듦) 모두 합쳐 하나만 남긴다. 폴더를 한 번도 만들지 않았고 표지도 고친 적이 없으면 올리지 않는다. 동기화 순서는 지운 문서 → 폴더 정리 → 문서 → (문서를 맞추며 충돌 사본을 폴더에 두는 등 정리가 바뀌었으면) 폴더 정리 다시.
  - 언제: 앱을 켤 때, 고친 뒤 15초 조용할 때, 앱을 내릴 때, 인터넷이 다시 연결될 때, 켜 두는 동안 3분마다.
  - 판단: 이 기기 `updatedAt` > `syncedLocalUpdatedAt`이면 "이 기기에서 고침", 드라이브 `updatedAt` ≠ `remoteUpdatedAt`이면 "다른 기기에서 고침". 한쪽만 고쳤으면 올리거나 받고, 양쪽 다 고쳤으면 다른 기기 쪽을 "제목 (다른 기기)" 사본으로 받아 두 판을 모두 남긴다(사본도 바로 올림). 이 기기에서 지운 문서는 드라이브에서도 지우고, 드라이브에서 사라진 문서는 이 기기에서 고친 적이 없을 때만 지운다.
  - 안드로이드 앱은 구글 Play 서비스의 AuthorizationClient로 권한을 받는다(앱 패키지명 + 서명 SHA-1로 등록한 Android OAuth 클라이언트, 앱 안에 비밀값 없음). 웹 버전은 Google Identity Services 토큰 방식이며 빌드 때 `VITE_GOOGLE_CLIENT_ID`가 필요하다.
- **PDF 내보내기(2차)**: pdf-lib으로 PDF 페이지에 필기를 벡터로 합성. HTML·URL 페이지는 제목과 "인터랙티브 페이지" 표시가 있는 대체 페이지 + 그 위 필기로 출력한다.

## 6. 화면 구성과 UX

화면은 상단 툴바, 왼쪽 썸네일 패널(접이식), 가운데 페이지 영역 세 부분이다. 수업 중에는 페이지 영역만 남긴다.

**홈 (문서 목록, v0.13 폴더)**

- 위: 새 문서 카드(PDF로 새 수업 · 빈 노트 · 파일 가져오기 · 필기감 시험지). 폴더 안에 있으면 그 폴더에 만든다고 알려 준다.
- 경로 막대: `내 문서 › 동아시아사 › 3단원` — 누르면 그 폴더로. 안드로이드 뒤로 가기는 선택 끝내기 → 찾기 지우기 → 윗 폴더 순. 문서를 열었다 돌아오면 보던 폴더.
- 도구: 찾기(모든 폴더의 문서·폴더 이름, 결과에 들어 있는 폴더 표시) · 정렬(최근 고친 순 / 이름 순, 기기에 기억) · 새 폴더 · 선택.
- 폴더 카드(색 아이콘, 이름, 안의 폴더·문서 수)가 먼저, 그 아래 문서 카드. 카드의 ⋮ 또는 길게 누르기(손가락 0.5초·펜 0.6초, PC 오른쪽 클릭) 메뉴: 폴더 — 열기 · 이름·색 바꾸기 · 옮기기 · 삭제 / 문서 — 열기 · 이름 바꾸기 · 표지 · 폴더로 옮기기 · 파일로 내보내기 · 삭제.
- 끌어서 옮기기: 카드를 길게 눌러 들린 뒤 끌어 폴더 카드나 경로 막대에 놓는다(PC는 마우스로 바로 끈다). 들린 채 움직이지 않고 떼면 메뉴.
- 선택: 여러 문서·폴더를 골라 한 번에 옮기기·표지·삭제(모두 선택 가능). 선택한 카드를 끌면 고른 것을 모두 옮긴다.
- 옮기기 창: 폴더 나무에서 고른다(옮기는 폴더 자신과 그 안의 폴더는 못 고름). 창 안에서 새 폴더를 만들어 바로 고를 수 있다.
- 이름 바꾸기·새 폴더는 앱 안 창(폴더는 색 8가지 중 고르기), 삭제는 확인 창.
- **문서 표지 (v0.21)**: 문서 카드(3:4)는 책 표지처럼 그린다 — 진한 표지 색 바탕, 왼쪽에 책등 띠, 위에 차시 번호를 크게("33", "3차시", "3-1"), 짧은 선, 그 아래 제목(낱말 단위 줄바꿈, 4줄까지), 아래쪽에 첫 페이지 종류(PDF · HTML · 웹 · 유튜브 · 그림 · 동영상 · 노트). 제목이 "33. …"·"7.…"·"3) …"·"3차시 …"·"3-1 …"처럼 번호로 시작하면 번호를 떼어 크게 쓰고, "6.25 전쟁"·"1592 임진왜란"·"19세기"는 번호로 보지 않는다(`doc/cover.ts`). 글자 크기는 카드 폭 비율(cqw)이라 화면 크기와 상관없이 같은 모양. 카드 아래 제목·쪽수·고친 때는 그대로.
  - 표지 색: 흰 글자 대비 4.5 이상인 10가지 — 남색 · 바다 · 청록 · 숲 · 올리브 · 황토 · 벽돌 · 자주 · 보라 · 먹. 기본은 **자동**(문서 id로 정해 이름을 바꿔도 그대로).
  - 메뉴의 **표지**(여럿은 선택 막대·메뉴의 "문서 N개 표지") → 표지 창: 그 문서 모양으로 그린 작은 표지들 중 자동 · 10가지 색 · **페이지 그림**(v0.21 "첫 페이지": 표지 대신 썸네일 페이지 그림을 통째로)을 누르면 바로 바뀌고 창이 닫힌다. 고른 표지는 폴더 정리와 함께 동기화된다(5장 `covers`).
  - **썸네일 페이지 (v0.22)**: 편집 화면의 페이지 바 ⋯ 메뉴(그 페이지)나 페이지를 길게 누른 메뉴(지금 페이지)의 **썸네일로 고르기** → 홈 카드 표지 아래쪽에 그 페이지가 흰 종이처럼 주머니에 꽂혀 위쪽 절반쯤 보인다(세로 페이지는 위 절반, 16:9 슬라이드는 거의 통째). 표지 번호·제목은 작아지고(제목 2줄, 번호 없으면 3줄) 종류 글자는 주머니 위로. 그림은 페이지 + 스티커 + 필기 + 글상자(`view/pageSnapshot.ts`, 폭 480px JPEG). 고른 페이지에는 페이지 바에 "썸네일" 표시가 붙고, 메뉴는 "썸네일에서 빼기"로 바뀐다. 알림 "2쪽을 문서 목록 썸네일로 골랐습니다…".
    - 그림은 페이지 구성을 저장할 때, 문서 목록으로 나갈 때, 앱을 내릴 때 지금 필기로 다시 만든다(바뀐 것이 없으면 그대로).
    - 다른 기기에서 고른 페이지, 또는 표지가 페이지 그림인데 이 기기에 그림이 없으면 홈이 그 문서를 열어 하나씩 만든다(원본을 아직 받지 못한 페이지는 나중에).
    - 표지 창 아래 줄: 꽂혀 있으면 **썸네일 빼기**, 없으면 고르는 방법 안내. 표지 색을 바꿔도 꽂힌 페이지는 그대로.

**색 (v0.19)**

- 펜 색 12가지: 교실 TV·프로젝터에서도 흐려 보이지 않게 진하고 쨍한 색 — 검정 `#111111` · 흰색 · 빨강 `#ff1e1e` · 파랑 `#0050ff` · 초록 `#00a844` · 주황 `#ff7b00` · 노랑 `#ffc800` · 보라 `#8f2bff` · 분홍 `#ff2d95` · 하늘 `#00a6ff` · 청록 `#00b3a6` · 갈색 `#9a5a1c`. 펜 설정 창에 7칸씩, 끝의 무지개 칸은 기기의 색 고르기 창(목록에 없는 색이면 그 칸에 그 색). 0.18까지의 파랑 `#1e5bd8`은 흐릿해 보였다.
- 형광펜 6가지: 형광 노랑 · 연두 · 하늘 · 분홍 · 주황 · 보라. 기본 펜 바: 형광 노랑 · 검정 · 빨강 · 파랑.

**형광펜 (v0.23)**

- 형광펜은 글자를 덮지 않는다. 형광펜 획만 펜 필기 아래 따로 한 층에 모아 칠하고, 그 층을 페이지와 **곱하기**(`mix-blend-mode: multiply`)로 섞는다. 곱하기는 밝은 곳(종이)만 물들이고 어두운 곳(글자·그림 선)은 그대로 두므로, 실제 형광펜처럼 글자는 원래 진하기 그대로 보이고 글자가 아닌 바탕에만 색이 든다. 색 글자는 형광 색과 곱해져 조금 짙어지고(파랑 → 짙은 남색), 짙은 바탕의 흰 글자는 형광 색으로 물든다.
- 층 진하기 75%(`HIGHLIGHTER_ALPHA`), 층 안에서는 형광펜끼리 불투명하게 겹친다(여러 번 그어도 겹친 곳이 더 짙어지지 않음). 0.22까지는 형광펜을 38% 반투명으로 글자 위에 덮어 글자가 흐려졌다(검은 글자가 밝기 95 정도로 연해짐).
- 펜은 언제나 형광펜 위: 펜으로 쓴 뒤 그 위를 형광펜으로 그어도 펜 글씨 색이 그대로다. 긋는 동안(떼기 전)에도 형광펜 층에서 그린다.
- 기본 형광 노랑을 더 밝은 레몬빛 `#fff200`으로(0.22까지 `#ffe600`). 흰 종이 위에서 `#fff540` 정도로 보인다. 예전 노랑 `#ffe600`으로 그은 획은 데이터는 그대로 두고 칠할 때 새 노랑으로 보여 준다(`LEGACY_HIGHLIGHTER`).
- 같은 규칙을 페이지 바 썸네일(형광펜 캔버스에 CSS 곱하기), 홈 표지 그림(JPEG에 캔버스 곱하기 합성), 도형 고치기 중 미리보기, 웹 페이지(판서 모드) 위에도 쓴다. 형광펜이 없는 페이지는 형광펜 층을 꺼 두고(큰 캔버스 메모리·합성 비용 없음), 처음 그을 때 켠다.
- 글상자 글자색 8가지: 검정 · 파랑 · 빨강 · 초록 · 주황 · 보라 · 분홍 · 흰색.
- **글상자 배경**: 고른 상자 막대의 배경 단추(페인트 통)에서 자동 · 없음 · 흰색 · 옅은 노랑·하늘·연두·분홍 · 회색 · 형광 노랑 · 짙은 남색. 새 글상자(붙여 넣은 글 포함)는 자동. 상자에서 고른 배경은 다음 새 상자에도 쓴다(글자색과 같이). 자동은 글자색에서 대비율(WCAG)을 재어: 진한 글자면 같은 빛깔의 아주 옅은 바탕(흰색 쪽으로 90~100%), 밝은 글자(흰색·노랑·주황)면 같은 빛깔의 아주 짙은 바탕(검정 쪽으로 82~100%) 중 대비 4.5 이상인 것, 없으면 3 이상(큰 글자 기준)인 것(`doc/colors.ts`). 글자색을 바꾸면 따라 바뀐다. 썸네일에도 같은 배경.

**글상자 서식 (v0.25)**

- 고른 상자 막대의 **서식** 단추(T)가 막대 아래에 서식 창을 연다(다시 누르면 닫힘). 상자 전체에 적용한다.
  - **글꼴** 5가지: 기본(고딕) · 명조(나눔명조) · 손글씨(연성) · 둥근(주아) · 제목(검은고딕). 단추 글자가 그 글꼴로 보인다. 기본 말고는 앱에 넣은 무료 글꼴(SIL OFL)이라 인터넷 없이도, 어느 기기에서나 같다. 글자 묶음(unicode-range)별 woff2 파일이라 쓰는 글자의 묶음만 그때그때 불러온다(약 8MB, 옛 woff 파일은 빼고 넣음). 웹(PWA)은 한 번 쓴 묶음을 남겨 둔다.
  - **글자 크기**: 16 · 20 · 24 · 30 · 38 · 48 · 60 · 72 · 96(지금 크기에 불이 들어옴). 크기가 정해진 상자는 글자가 그 크기쯤 되도록 상자를 같은 비율로 키우거나 줄인다(줄바꿈 모양은 그대로). 막대의 글자 작게/크게도 이 단계를 따른다(0.24까지는 60이 가장 큼).
  - **굵게 · 기울임 · 밑줄**(켜고 끔) · **줄 맞춤** 왼쪽 · 가운데 · 오른쪽. 크기가 정해진 상자는 상자 폭 안에서, 아니면 가장 긴 줄 폭 안에서 맞춘다.
- 글꼴·굵게·기울임을 바꾸면 그 글꼴로 너비를 다시 재어 줄을 나누고, 크기가 정해진 상자는 글자 크기를 다시 맞춰 적어 둔다. 글꼴 파일이 늦게 오면 받는 대로 다시 재서 그린다. 썸네일·표지 그림은 그리기 전에 그 글꼴을 받아 둔다(캔버스는 글꼴을 스스로 불러오지 않음).
- 고른 서식(글꼴·굵게·기울임·밑줄·줄 맞춤)과 글자 크기는 다음 새 상자(붙여 넣은 글 상자 포함)에도 쓴다(글자색·배경·테두리와 같이).

**글상자 애니메이션 (v0.26 · 쪽지·강조 v0.28)**

- 고른 상자 막대의 **애니메이션** 단추(반짝이)가 창을 연다(링크·베일 상자에는 없음). 막대를 상자 위에 둘 자리가 모자라면(창을 펼치면 더 필요) 상자 아래에 둔다. 고른 상자에서 연 창은 상자를 옮기거나 크기를 바꾸거나 미리 보기를 해도 그대로 열려 있다.
  - **나타나기**: 늘 보임 · **쪽지 접기**. 쪽지 접기면 **쪽지 색** 5가지(노랑·분홍·민트·하늘·라벤더) · **타자 효과** 켜고 끔(처음엔 켜짐) · **크기**(밀대, 페이지 가로 3~15%) · **쪽지 글**(8자까지, 비우면 "?"). 창을 연 동안 상자 왼쪽 위에 접혔을 때의 쪽지가 점선 테와 함께 보여 크기·색·글을 바꾸면 바로 보인다.
  - **강조**: 없음 · 형광펜 · 통통 · 반짝.
  - **미리 보기**: 쪽지 접기면 접힌 쪽지(0.8초) → 펼치기 → 타자 → 강조, 강조만이면 강조. 미리 보기의 형광펜은 2.2초 뒤 지워진다.
  - 텍스트 모드에서 애니메이션이 있는 상자는 오른쪽 위에 작은 표시(쪽지 접기면 쪽지, 강조만이면 반짝이).
- **강의 모드 — 쪽지 접기**: 상자 왼쪽 위 모서리에 살짝 걸쳐 붙은 **포스트잇 쪽지**로 보인다(0.26의 두루마리 띠는 상자 폭만큼 커서 바꿈). 정사각형, 위쪽에 반투명 마스킹테이프, 오른쪽 아래가 살짝 들린 모서리, 상자마다 조금씩 다르게 기울어짐(-4.5°~4.5°), 손글씨(연성)로 쓴 쪽지 글(한 글자면 크게, 4자까지 한 줄, 더 길면 두 줄). 상자에서 나가거나 들어오는 화살표도 접혀 있는 동안 감춘다.
  - 쪽지를 누르면(손가락·S펜, 필기층 위라 펜으로 눌러도 글씨가 되지 않음) 쪽지가 떼어져 오른쪽 위로 날아가며 사라지고, 상자는 쪽지 자리(왼쪽 위)에서부터 오른쪽 아래로 펼쳐진다(0.52초). 이어 화살표가 시작 상자에서 끝 쪽으로 그려져 나간다(0.45초).
  - 타자 효과면 펼친 뒤 글자가 한 자씩 입력되듯 나온다: 한글은 두벌식 입력처럼 자모가 조합되고(ㅇ → 오 → 와 → 왕), 받침 없는 글자 뒤 자음은 잠깐 앞 글자 받침이 됐다가 다음 글자로 넘어간다(고 → 골 → 고려). 줄이 바뀌는 곳에서는 넘어가지 않는다. 한 번 누름(자모·글자)에 0.04~0.07초 안팎(사람처럼 조금씩 다른 박자, 띄어쓰기·문장부호 앞은 조금 쉼), 아무리 길어도 2.6초 안. 친 글자 뒤에 깜빡이는 커서, 다 치면 0.65초 깜빡이고 사라진다. 아직 안 친 글자도 자리를 차지해(안 보이게) 줄 모양·맞춤이 처음부터 같다. 펼치는 중에 상자를 누르면 바로 다 보인다. 강조가 있으면 다 펼친 뒤(다 친 뒤) 한 번 강조.
  - 펼친 상자 위로는 필기가 지나간다(밑줄·형광펜). 상자 오른쪽 위의 작은 ⌃ 단추(반투명)로 다시 접는다(상자가 왼쪽 위로 접혀 들어가고 쪽지가 다시 붙음, 0.36초).
  - 펼친 상태는 강의 모드 동안 기억한다(다른 쪽에 갔다 와도 펼친 그대로). 강의 모드를 끝냈다 다시 시작하면 모두 접힌다.
- **강의 모드 — 강조**: 강조가 있는 상자를 **손가락(PC는 마우스)으로 톡** 누르면(10px 안, 0.6초 안에 뗌) 강조. 상자는 필기가 지나가야 하므로 누름을 가로채지 않고 누른 자리로 찾는다 — S펜으로 누르면 강조가 아니라 필기.
  - **형광펜**: 글 아래(글자 높이의 아래쪽 절반)에 노란 형광펜이 왼쪽에서 오른쪽으로 쓱 칠해진다(줄마다 0.22초씩 늦게, 0.5초). 칠한 채 남고, 다시 누르면 지워진다. 강의 모드를 끝내면 지워진다.
  - **통통**: 상자가 위로 튀었다 내려앉으며 두어 번 출렁인다(0.75초).
  - **반짝**: 상자 둘레가 금빛으로 빛나고 빛 한 줄기가 비스듬히 지나간다(1.1초).
- 강의 모드가 아니면 늘 펼친 그대로·강조 없이 그린다(평소 보기·텍스트 모드·페이지 바 썸네일·표지 그림).

**베일 (v0.28)**

- 학습지 빈칸에 인쇄된 정답, 미리 써 둔 글상자·그림 등 **페이지의 어느 곳이든 가려 두었다가** 수업 중 걷어 보이는 천. (이름: "베일을 벗기다" — 감춰진 것이 드러남)
- 만들기: 도구 막대의 **베일** 단추(블라인드) → 텍스트 모드의 베일 그리기가 켜지고 "가릴 곳을 끌어서 베일을 씌우세요" → 가릴 곳을 **끌면** 그 네모(끄는 동안 점선 네모)대로 베일이 생긴다. 톡 누르면 그 자리가 가운데인 기본 크기(페이지 가로 16% × 세로 5%), 고른 것이 있으면 톡은 고르기만 풀기. 여러 개를 이어서 만들 수 있고, 같은 단추·다른 도구로 끝낸다. 페이지를 길게 누른 메뉴의 "베일 (가리기)"도 그 자리에 기본 크기로.
- 고치기(텍스트 모드): 글상자처럼 끌어 옮기고 손잡이로 크기. 막대는 **베일 글**(베일 위에 보일 짧은 글, 비우면 "?") · **색** 5가지(남색 벨벳·버건디·숲·먹·모래) · 복사 · 잘라내기 · 지우기. 글이 없어도 지워지지 않는다. 길게 누른 메뉴는 "베일"(링크·화살표 없음).
- 강의 모드가 아닐 때(평소 보기·텍스트 모드·썸네일)는 그 밑이 보이게 반투명(색 42%)·점선 테두리.
- **강의 모드**: 그 색의 벨벳 천(비스듬한 윤기, 세로 주름, 아래쪽 그늘, 둥근 모서리)으로 완전히 덮고 가운데에 베일 글. 필기층·글상자·팝업 아이콘 위. 손가락·S펜으로 누르면 천이 위로 들리며 펄럭이고 비스듬히 날아가 사라진다(0.62초). 걷은 자리 오른쪽 위의 작은 단추(반투명)로 다시 씌운다(천이 내려앉음). 걷은 상태는 강의 모드 동안 기억하고, 강의 모드를 다시 시작하면 모두 덮인다.

**글상자 테두리·화살표 (v0.20)**

- **테두리**: 고른 상자 막대의 테두리 단추(네모)에서 없음 · 글자색(글자색을 따라감) · 8가지 색(글자색과 같은 목록) · 굵기 얇게/보통/굵게. 상자 안쪽에 그려 상자 크기·자리는 그대로, 모서리는 둥글게. 고른 테두리는 다음 새 상자에도 쓴다(글자색·배경과 같이). 썸네일에도 같은 테두리.
- **화살표** (v0.20 상자 잇기 → v0.24 아무 곳 가리키기): 고른 상자 막대의 화살표 단추, 또는 상자를 길게 누른 메뉴의 "화살표" → 화면 위에 "화살표 끝을 둘 곳이나 이을 상자를 누르세요 · 그만" 안내.
  - **아무 곳을 누르면**(줄 그은 곳·그림·글자 등, v0.24) 상자 → 그곳을 가리키는 화살표(`at`), 촉 끝이 누른 자리에 닿는다. 글상자로 페이지의 어느 부분을 설명할 때 쓴다. 한 상자에서 여러 곳을 가리킬 수 있다.
  - **다른 상자를 누르면** 두 상자를 잇는다(`to`, 0.20과 같음). 같은 두 상자 사이에는 하나만(이미 있으면 그것을 고름).
  - 처음 상자를 다시 누르거나, 안내의 "그만", Esc면 그만. (0.23까지는 빈 곳을 누르면 그만이었다.)
- 화살표는 시작 상자 가운데에서 끝(상자 가운데 또는 가리키는 곳)으로 가는 선을 시작 상자 가장자리에서 조금 띄워 자르고, 끝이 상자면 그 가장자리 앞에서, 가리키는 곳이면 그 점에서 촉 끝. 상자를 옮기거나 크기를 바꾸면(끄는 중에도) 시작(과 이어진 끝)이 따라가고, 가리키는 곳은 그대로다. 끝이 시작 상자 안이면 그리지 않는다. 필기 위, 글상자 아래에 그린다.
- 텍스트 모드에서 화살표를 누르면 골라지고(빛나는 테) 손잡이 둘과 막대가 나온다.
  - **끝 손잡이**(흰 동그라미, v0.24): 끌면 화살 끝이 따라오고, 다른 상자 위에 놓으면 그 상자로 이어지고, 빈 곳에 놓으면 그곳을 가리킨다(상자로 이은 화살표를 떼어 아무 곳을 가리키게도). 상자로 이은 화살표는 손잡이가 상자를 가리지 않게 촉 끝에서 조금 뒤에. 톡 누르기만 하면 바뀌지 않는다.
  - **휘기 손잡이**(점선 동그라미, 곡선 가운데, v0.24): 끌면 곡선 가운데가 그 자리를 지나도록 휜다(`bend`, 2차 베지어). 곧은 선 근처(길이의 3% 안)로 되돌리면 곧게. 촉은 곡선이 끝나는 방향.
  - 막대: 방향 바꾸기(상자끼리 이은 것만, 휜 쪽은 그대로 보이게) · 양쪽 화살표 · 색 7가지(흰색 빼고) · 화살표 지우기(알림의 "되돌리기"). Delete 키로도 지움. 끄는 동안은 막대를 감춘다. 다른 도구일 때는 화살표를 눌러도 고르지 않고 그 위로 필기가 된다.
- 상자를 지우면 그 상자에 이어진 화살표(그 상자에서 나간 가리키는 화살표도)도 지워지고, 되돌리기는 둘 다 살린다. 페이지 복제·잘라내기/복사해 붙이기·다른 문서로 보내기는 상자와 화살표를 함께 옮긴다(새 상자 id로 이어 줌, 가리키는 곳은 그대로). 상자만 복사해 붙이면 화살표는 따라가지 않는다.

**입력 규칙 (스타노트 사용감 맞추기)**

- S펜 = 필기, 손가락 = 페이지 넘김·확대 (손바닥 오인식 방지). 설정에서 "손가락으로도 필기" 옵션 제공.
  - 손가락: 두 손가락 = 확대·축소와 이동, 확대 상태의 한 손가락 = 이동, 두 번 탭 = 확대 ↔ 원래 크기, 좌우로 쓸기 = 페이지 넘김.
  - "손가락으로도 필기"를 켜면 한 손가락은 필기, 두 손가락은 확대·이동 (쓰던 손가락 획은 취소).
  - **펜과 손 구분** (v0.17): 필기·확대·길게 누르기는 웹뷰가 넘기는 `pointerType`을 그대로 믿지 않고 닿는 순간 한 번 정한 종류(`inputState.pointerKind`: pen·mouse·touch)를 뗄 때까지 쓴다.
    - 안드로이드 앱: 갤럭시탭의 S펜은 손가락 터치 화면과 따로 있는 펜 감지판(디지타이저)으로 들어와 안드로이드가 도구 종류(STYLUS / FINGER)를 확실히 안다. 앱(`PenInput.java`)이 닿은 것마다 도구·자리(웹뷰 기준 화면 px)·접촉 크기를 기억하고(뗀 것은 1초까지), 웹 화면은 pointerdown 때 `LessonDeckPen.toolAt(clientX×dpr, clientY×dpr)`로 물어(24px 안의 닿아 있는 것 중 가장 가까운 것, 없으면 막 뗀 것) stylus면 펜, finger·그 밖의 도구면 손으로 정한다. 손가락이 펜으로 오거나 S펜이 손가락으로 와도 바로잡힌다. 앱이 모르면("none") 아래 규칙.
    - pointerType이 `pen`·`mouse`가 아니면(손바닥 등 종류를 알 수 없는 `""` 포함) 손으로 본다 — 0.16.2까지는 종류를 알 수 없는 접촉이 손가락 필기를 꺼 두어도 글씨가 되고 확대에서는 빠졌다.
    - 펜으로 왔어도 접촉이 16 CSS px 이상으로 굵으면 손으로 본다(S펜 촉은 1~2px).
    - **펜 모드** (오픈소스 화이트보드 Excalidraw·tldraw의 pen mode와 같은 방식): "손가락으로도 필기"를 켜 둔 채 S펜이 닿으면 손가락 필기를 끄고 알린다. 끈 뒤 ✋로 다시 켜면 이번 실행 동안은 그대로 둔다.
    - 입력 디버그에 "펜/손 판정"(앱의 답·접촉 크기)과 최근 입력 기록, 복사하는 보고서에도 넣는다.
  - 뗌 이벤트를 놓쳐도 꼬이지 않게 (v0.16.2): 첫 손가락(isPrimary)이 닿으면 남아 있던 손가락 기록은 지운다(남기면 한 손가락을 두 손가락 확대로 보거나 손가락 필기를 막음). 펜이 다시 닿았는데 지난 펜 획이 열려 있으면 지난 획을 거기서 마무리하고 새 획을 시작한다(지난 획 끝에 이어 붙어 엉뚱한 선이 생기지 않게).
- **S펜 사이드 버튼 = 지우개** (2026-10-25 사용자 요청으로 변경): 누르고 있는 동안 툴바의 지우개가 켜지고, 그 상태로 쓰면 지워지며, 떼면 원래 펜으로 돌아간다.
  - 안드로이드 앱(v0.16.1~): 웹뷰(크로미움)는 S펜 버튼 상태를 제대로 받지 못한다 — 삼성 기기는 버튼을 누른 채 닿으면 표준 대신 삼성 동작 번호(211 닿음·213 움직임·212 뗌)를 보내 웹뷰가 무시하고(손바닥이 닿아 있으면 표준 번호라 될 때도 있었음), 버튼을 떼는 순간 표준 움직임으로 바뀌어 갑자기 글이 써졌다. 또 표준 버튼 상태는 "버튼 누른 채 끌기 = 글자 고르기"로 가로챈다. 그래서 앱(`PenInput.java`)이 화면 터치를 웹뷰보다 먼저 받아 모든 펜 이벤트를 표준 동작·버튼 없음으로 바꿔 넘기고, 펜이 닿는 순간(DOWN·펜의 POINTER_DOWN) 버튼이 눌려 있었는지를 그 획의 "지우개 여부"로 기억한다. 웹 화면은 펜 획을 시작할 때 앱이 붙여 둔 `window.LessonDeckPen.strokeErase()`(JavascriptInterface, 웹뷰의 별도 스레드에서 바로 답함)로 물어 그 획 전체(뗄 때까지)를 정한다 — 중간에 버튼을 떼거나 눌러도 바뀌지 않는다. 버튼 상태 변화는 `lessondecksidebutton` 이벤트로 알려 도구 막대 지우개 표시에만 쓴다(입력 디버그에 원래 동작 번호·버튼·도구 기록). 지우개는 이벤트 사이를 이어서 지운다(빠르게 쓸어도 가는 획을 빠뜨리지 않음). 삼성 동작 번호가 손가락·손바닥과 함께 오면 그 펜의 POINTER_DOWN/UP으로 바꾼다(DOWN/UP으로 바꾸면 웹뷰가 손가락까지 끝난 것으로 봄).
    - **펜을 띄운 채 버튼을 누르면 글씨가 써지던 문제** (v0.26): S펜 커서(호버)가 보이는 상태에서 버튼을 누르면, 웹뷰가 버튼 상태가 실린 호버를 "왼쪽 버튼을 누른 펜"(닿음)처럼 넘겨 닿지 않았는데 획이 시작됐다. 고침: ① 앱이 펜 호버 이벤트에서 버튼 상태를 빼고 넘기고, 펜의 버튼 누름·뗌 이벤트(`ACTION_BUTTON_PRESS/RELEASE`)는 웹뷰에 넘기지 않는다(버튼 상태는 앱이 `lessondecksidebutton`으로 따로 알림 → 지우개 표시·지우개 커서는 그대로). ② 웹 화면은 앱에서 펜 획을 시작하기 전에 `LessonDeckPen.stylusTouching()`으로 S펜이 정말 화면에 닿아 있는지(앱이 기억하는 닿은 S펜, 막 뗀 것은 0.5초까지) 한 번 더 묻고, 아니면 획을 시작하지 않는다. 물을 수 없는 옛 앱·브라우저는 예전 규칙.
    - 0.16.1은 `prompt()`로 물었는데, 웹뷰는 JS 대화창이 열린 동안 그 화면으로 가는 입력을 버린다. 펜이 닿을 때마다 잠깐씩 터치가 사라져(손가락 뗌, 펜 뗌) 확대·축소가 어긋나고, 다음 펜 획이 지난 획 끝에 이어 붙어 갑자기 선이 생겼다 → 0.16.2에서 대화창 없는 JavascriptInterface로 바꿈. 대화창(prompt·alert·confirm)으로 앱과 주고받지 않는다.
- **직선 보정 (v0.16, 기본 켬)**: 펜·손가락으로 긋다가 떼지 않고 0.5초 멈추면 그은 획이 시작점에서 지금 자리까지 직선이 된다(획 길이가 짧으면 그대로). 떼기 전까지 움직이면 끝점(각도·길이)이 따라오고, 수평·수직·45°에 가까우면(±4°) 붙는다. 굵기는 그 획의 평균 필압. 형광펜에도 된다. 길게 누르기 메뉴(누른 자리에서 움직이지 않고 누름)와는 겹치지 않는다.
- **도형 보정 (v0.18, 직선 보정을 넓힘, 기본 켬)**: 긋다가 떼지 않고 0.5초 멈추면 그 획을 알아본 도형으로 바꾼다(`shapeRecognize.ts`). 도형이 아니면 곡선(v0.24, 아래), 그것도 아니면 위 직선.
  - 알아보는 법: 획을 고르게 다듬고, 끝이 시작 근처로 돌아왔으면(조금 지나치거나 덜 닫아도: 틈이 크기의 22% 또는 그은 길이의 12% 안) 닫힌 모양. 고른 간격 96점으로 다시 찍은 뒤
    1) (v0.18.1) 큰 모양은 공개된 CALI 인식기의 넓이 비로: 볼록 껍질이 가장 작은 둘레 사각형을 83% 넘게 채우면 사각형(원·타원은 π/4 ≈ 79% 아래, 모서리가 둥글거나 변이 휘어도 82% 넘음), 껍질 안의 가장 큰 삼각형이 껍질을 85% 넘게 채우면 삼각형(원은 41%, 사각형 50%). 0.18.0은 모서리 찾기만 써서 둥근 모서리·휜 변·덜 닫은 사각형이 원이 되거나 아무것도 안 되곤 했다.
    2) 나머지는 공개된 ShortStraw 방법(앞뒤 3점 사이 거리가 짧아지는 곳 = 모서리)으로 모서리를 찾고, 모서리 사이가 모두 곧으면(굽은 정도 8% 미만) 다각형(별은 1보다 먼저), 그렇지 않으면 주성분 방향으로 맞춘 타원과 오차를 견줘 원·타원.
  - 원·타원(거의 동그라면 원, 축이 가로·세로 ±10°면 바로 세움) · 사각형(네 각이 90±13°, 기울기 ±8°면 바로, 가로세로가 10% 안이면 정사각형, 기울어진 사각형은 그 각도) · 마름모(두 대각선이 가로·세로) · 삼각형(밑변이 가로이고 꼭대기가 가운데면 이등변, 그 밖은 그린 꼭짓점대로) · 오각형·육각형(변 길이·각이 고르면 정다각형) · 별(한 번에 그린 오각별, 또는 꼭짓점 10개) · 그 밖의 다각형(가로·세로 ±7°인 변은 딱 맞춤) · 화살표(긴 줄기 끝에서 양쪽으로 꺾인 짧은 날개, 열린 획).
  - **곡선 (v0.24)**: 0.23까지는 도형이 아닌 획은 모두 직선이 되어, 휘어지게 그은 선(밑줄 그은 곳을 가리키는 휜 화살표 등)도 곧아졌다. 이제 도형이 아니면 `curveFit.ts`가 곡선을 맞춰 본다.
    - 획을 고르게 다듬고, 뒤쪽 45% 안에서 처음으로 크게(115° 넘게) 되꺾인 곳이 있으면 그 근처에서 줄기 방향으로 가장 멀리 나간 점을 촉 끝으로 본다. 그 뒤가 촉 끝 근처(줄기의 45% 안)에 머물고, 60% 넘게 줄기 쪽(뒤)으로, 한쪽이라도 6px·줄기의 3% 넘게 벌어지면 휜 화살표(날개 한쪽만 그어도).
    - 줄기(화살표가 아니면 획 전체)를 두 끝을 지나는 3차 베지어 하나로 맞춘다(Schneider 방법: 길이 비율로 t를 정하고 최소제곱으로 두 조절점, 뉴턴법으로 t를 4번 다듬음). 맞춘 곡선과 다듬은 점·원래 점 모두 가까우면(줄기 곧은 길이의 7%·5px 안, 원래 점은 1.4배까지) 곡선 — C자·S자 모두. 맞춘 곡선이 곧은 선에서 8% 넘게 벗어나지 않으면 곧은 것으로(물결·손떨림은 평균으로 사라짐).
    - 작은 획(그은 길이 60px·곧은 길이 40px 미만, 글씨 획), 많이 돌아가는 것(그은 길이가 곧은 길이의 2.6배 넘음: 고리·소용돌이), 맞지 않는 것(지그재그·여러 번 출렁이는 물결)은 곡선이 아님.
    - 결과: 곡선 → 곡선 선(`line` + `curve`), 휜 화살표 → `arrow` + `curve`(촉은 곡선이 끝나는 방향), 곧은 화살표 → `arrow`, 곧은 선 → 위 직선(떼기 전까지 끝점이 따라옴).
  - 닫힌 도형·화살표·곡선은 그대로 두고, 직선은 떼기 전까지 끝점이 따라온다. 도형·직선·곡선은 도형 획(5장)으로 저장하고 떼면 바로 고른 상태가 된다.
- **도형 모드 (v0.18.1, 0.18.0의 "도형 넣기"를 바꿈)**: 도구 막대의 도형 단추(또는 길게 누르기 페이지 메뉴의 "도형")가 여는 창에서 도형을 고르거나 "자동"을 고르면 도형 모드가 켜진다(도형 단추가 켜지고 이름이 "도형 모드 (사각형)" 등).

  - 자동: 평소처럼 그린 획을 뗄 때(멈추지 않아도) 도형 보정과 같은 방법으로 알아본 도형으로 바꾼다(곡선·휜 화살표도, v0.24). 모르는 모양(글씨 등)과 곧은 획은 쓴 그대로.
  - 지금 고른 펜·형광펜의 색·굵기로 그린다. 끝내기: 창의 "도형 모드 끄기", 도구 막대의 펜·형광펜·지우개, 펜 바에서 펜 고르기, 텍스트 모드. S펜 버튼 지우개는 도형 모드에서도 지우개.
- **도형 고치기 (v0.18)**: 고른 도형에 손잡이 — 네 모서리(비율 유지, 맞은편 모서리 고정)·네 변(그 방향만, 맞은편 변 고정)·위 손잡이(돌리기, 15° 배수 ±4°에 붙음)·가운데(옮기기). 선·화살표는 두 끝(가로·세로·45° 근처 붙음, 곡선이면 곡선 모양 그대로)과 **휘기 손잡이**(v0.24, 곡선 가운데의 점선 동그라미: 끌면 곡선 가운데가 그 자리를 지나도록 두 조절점을 같이 옮김, 곧은 선도 휘어짐, 거의 곧게 되돌리면 곧은 선), 옮기기 손잡이는 휘기 손잡이와 겹치지 않게 휜 쪽 반대로 조금 떨어져 있다. 작은 막대에 복제·지우기·완료. 끄는 동안은 바뀐 모양을 미리 보여 주고, 손을 떼면 한 번에 저장(실행 취소 한 단계).

- **필기 보정 (v0.16, 기본 켬)**: 펜 획을 뗄 때 글씨를 반듯하게 다듬는다(형광펜·직선 제외). 획을 고르게 다시 찍은 뒤 꺾인 곳(45° 넘게 꺾임)은 그대로 두고, 그 사이 거의 곧은 부분은 직선으로, 수평·수직에 가까운(±6°) 직선은 수평·수직으로 맞추며(이어진 뒷부분도 함께 옮겨 이음새 유지), 굽은 부분(ㅇ 등)은 부드럽게, 필압은 고르게 한다. 짧은 점·획은 그대로.

**발표 모드 (화면 이름: 강의 모드, F10)**

- 상단 바의 강의 모드 버튼(PC는 F5)으로 들어간다. 상단 바·도구 막대·페이지 바·디버그 패널이 숨고, 페이지가 여백 없이 화면 가득(가로세로 비율 유지, 남는 곳은 검정) 커진다. 브라우저에서는 전체 화면도 함께 켠다.
- 남는 것: 왼쪽 펜 팔레트, 떠 있는 페이지 넘기기 바. 강의 모드의 넘기기 바에는 실행 취소·지우개·(웹앱·동영상 페이지) 판서/조작 전환·끝내기 버튼이 붙는다. S펜 사이드 버튼 지우개, 손가락 넘김·확대는 그대로 동작한다.
- **스포트라이트 (v0.28)**: 강의 모드 넘기기 바의 **스포트라이트** 단추(손전등)로 켜고 끈다. 페이지 화면을 80% 어둡게 하고 S펜(띄운 채 움직여도)·손가락·마우스가 있는 곳만 동그랗게 밝힌다(가장자리 16px는 부드럽게). 처음엔 화면 가운데. 켜진 동안 바에 작게/크게(반지름 80·120·170·230·310px, 기기에 기억, 처음 170). 누름은 모두 지나가 그 밑에서 그대로 판서·넘기기·누르기. 넘기기 바는 위에 남는다. 강의 모드를 끝내면 꺼진다.
- 끝내기: 바의 끝내기 버튼, Esc, 안드로이드 뒤로 가기(앱을 닫기 전에 강의 모드부터 끝낸다), 브라우저 전체 화면 해제.
- **키로 넘기기**: →·PageDown 다음, ←·PageUp 이전(블루투스 S펜·발표 리모컨·키보드). (v0.18.2) 누르고 있어 자동으로 되풀이되는 키(`repeat`)는 무시해 한 번 누름에 한 쪽만 넘긴다 — 0.18.1까지는 키를 누르고 있으면 끝 쪽까지 쭉 넘어갔다. Enter·Space의 되풀이도 막고, 넘기기 바 단추는 누른 뒤 초점을 놓아(되풀이되는 Enter가 그 단추를 계속 누르지 않게). S펜 버튼을 누르고 있거나 막(0.7초 안) 뗐을 때 들어온 넘김 키는 무시한다(화면 가까이에서 버튼을 지우개로 쓸 때 블루투스 S펜이 함께 보내는 키). 입력 디버그에 들어온 키(웹·앱: 키 이름·장치·반복)를 적는다.
- **링크로 본 쪽 건너뛰기 (v0.18, 강의 모드, 기본 켬)**: 강의 중 페이지 링크로 다른 쪽에 갔다가 링크(돌아가기 링크 등)로 되짚어 오면 들렀던 쪽을 "링크로 본 쪽"으로 기억한다(A → P → Q → P → A면 Q, P 차례로). 켜 두면 다음·이전(넘기기 바, 쓸어 넘기기, 키보드)이 그 쪽을 숨긴 쪽처럼 건너뛰고 "링크로 본 5쪽은 건너뜁니다"로 알린다. 화면 위 가운데의 작은 단추("링크로 본 쪽 건너뛰기 켬/끔 · N쪽")로 켜고 끈다(기기에 저장). 기록은 강의 모드를 시작할 때마다 새로, 페이지 바·링크로 직접 가는 것은 막지 않는다(`doc/detours.ts`).
- **길게 누르기 메뉴**: 펜(0.6초)·손가락(0.5초)으로 움직이지 않고 누르고 있으면(누른 자리에 원이 차오름) 메뉴, PC는 오른쪽 클릭. 글상자 위면 상자 메뉴(링크 열기·글 고치기·링크·크기·위치·복사·잘라내기·복제·붙여넣기·지우기), 스티커 위면 스티커 메뉴(크기·위치·자르기·꾸미기·복사·잘라내기·복제·붙여넣기·맨 앞/뒤·지우기), 빈 곳이면 페이지 메뉴(붙여넣기·글상자·링크·이미지, 실행 취소·다시 실행, 필기 지우기, 빈 페이지 추가·페이지 복제·복사·잘라내기, 새로고침, 강의 모드). 누른 자리에 들어가므로 메뉴 이름에 "여기에"를 붙이지 않는다(v0.16 메뉴 이름 줄임). 펜으로 누른 점은 그리지 않는다. 지우개로 지우는 중, 떠 있는 도구(팔레트·넘기기 바) 위에서는 열지 않는다.
- **이미지 스티커 (v0.14)**: 도구 막대의 **이미지 스티커** 단추(또는 페이지 길게 누르기 → 여기에 이미지)로 그림을 골라 지금 페이지에 붙인다. PC는 그림 파일을 끌어 놓거나 Ctrl+V(복사한 그림)로도 붙인다. 붙인 스티커는 골라진 상태:
  - 끌어서 옮기기, 모서리 손잡이로 크기(비율 유지), 위 동그라미 손잡이로 돌리기(15° 단위로 붙음), 빈 곳을 누르면 고르기 끝.
  - 위에 뜨는 막대: 자르기 · 90° 돌리기 · 좌우 뒤집기 · 꾸미기(모양 사각·둥근·원 / 테두리 없음·흰 스티커·검정·색, 굵기 / 그림자 / 투명도) · 맨 앞으로 · 맨 뒤로 · 복사 · 잘라내기 · 지우기.
  - 자르기: 그림 전체가 흐리게 보이고 보일 부분을 8개 손잡이로 정한다(끌어서 옮기기도). 완료·취소·원래대로.
  - 다시 고치기: 스티커를 길게 누르거나(PC 오른쪽 클릭) 텍스트 모드에서 누르면 메뉴·고르기.
  - **팝업 그림 (v0.27)**: 고른 스티커 막대의 **팝업** 단추(또는 스티커 길게 누르기 메뉴의 "팝업 (누르면 크게)")로 켜고 끈다.
    - 켜면 스티커가 같은 가운데 자리의 작은 정사각형 **아이콘**(처음 페이지 가로 7%)이 된다: 그림 가운데를 꽉 채운 둥근 모서리·흰 테두리·그림자, 오른쪽 아래에 크게 보기 표시(⤢). 작아서 글을 가리지 않게 구석이나 빈 곳에 둔다. 모서리 손잡이로 **아이콘 크기**(페이지 가로 3~50%), 끌어서 자리, 돌리기·꾸미기(모양·테두리)도 아이콘에. 팝업이 켜진 동안 자르기는 쓸 수 없다(끄고 원래 크기에서).
    - 아이콘은 필기·글상자 위에 있어 **누를 수 있다**: 손가락·S펜·마우스로 톡 누르면(10px 넘게 움직이거나 길게 누르면 아님) 그 페이지 위에 크게 뜬다 — 페이지가 어두워지고(58%), 그림이 아이콘 자리에서 페이지 가운데로 커지며(0.32초) 원래 비율로 페이지 가로 92%·세로 88% 안에 가장 크게. 아이콘 자리는 비워 둔다. 펜으로 눌러도 글씨가 되지 않는다.
    - 닫기: 그림 바깥(어두운 곳)을 누르거나, 그림 오른쪽 위 ✕, Esc, 안드로이드 뒤로 가기 → 아이콘 자리로 작아지며(0.24초) 닫힌다. 그림 위를 누르면 그대로. 다른 쪽으로 넘어가면 닫힌다. 강의 모드에서 Esc·뒤로 가기는 먼저 그림을 닫고, 한 번 더 누르면 강의 모드를 끝낸다.
    - 텍스트 모드이거나 스티커·도형을 고친 중이거나 화살표 끝을 고르는 중에는 아이콘을 눌러도 열지 않고(누름이 지나감) 텍스트 모드에서는 그 스티커가 골라진다. 길게 누르기(PC 오른쪽 클릭)는 스티커 메뉴.
    - 끄면 원래 크기 스티커로 돌아간다(아이콘 가운데 자리에). 썸네일·표지 그림에는 아이콘 모양으로.
- **다른 앱에서 복사한 것 (v0.15)**: 붙여넣기는 늘 보인다(도구 막대 단추, 길게 누르기 메뉴, 페이지 바 + 메뉴 맨 위, 페이지 ⋯ 메뉴). 페이지 안에서 붙이면 페이지 안에(그림은 스티커, 링크·글은 글상자), 페이지 바에서 붙이면 새 페이지로(그림 페이지, 웹 주소·유튜브 페이지, 글상자가 있는 빈 페이지).
- **페이지 복사·붙여넣기 (v0.14)**: 페이지 바에서 고른 페이지의 ⋯ 단추(또는 PC 오른쪽 클릭), 페이지 길게 누르기 메뉴로 복사·잘라내기·앞/뒤에 붙여넣기. 페이지 바 사이의 + 메뉴 맨 위에 "여기에 붙여넣기". 다른 문서를 열어 붙이면 그 문서에 그대로 들어간다.
- **상단 바**: 문서 목록 · 제목(누르면 이름 바꾸기) … 동기화 · **강의 모드**(강조 단추) | 페이지 바 · 페이지 추가 · 손가락 필기 · ⋮ 더보기(이름 바꾸기, 파일로 내보내기, 펜 바·페이지 바·입력 디버그 켜고 끄기). 도구 막대는 가운데 정렬, 켜진 도구는 강조색.
- **페이지 넘기기 바**는 손잡이나 쪽수를 잡고 끌어 화면 어디로든 옮길 수 있다(페이지 영역 밖으로는 못 나감). 위치는 남는 공간 대비 비율로 기기에 저장해 화면 방향이 바뀌어도 비슷한 자리에 있고, 손잡이를 두 번 누르면 아래 가운데로 돌아간다.

## 7. 개발 단계

Phase 0의 태블릿 필기감 검증을 통과해야 다음 단계로 간다. 필기감이 스타노트에 크게 못 미치면 구조(웹앱 → 네이티브 셸)를 재검토한다.

| Phase | 내용 | 완료 기준 (갤럭시탭 실기기) |
| --- | --- | --- |
| 0. 필기감 검증 | PDF 1쪽 렌더링 + S펜 필기 캔버스만 있는 시험 페이지 | 지연이 체감상 거슬리지 않음, 필압 반영, 손바닥 오인식 없음 |
| 1. 페이지 시퀀스 | PDF 불러오기, 페이지 목록, 넘기기, HTML 파일·URL 페이지 삽입, 숨기기 | 10쪽 PDF의 2쪽 뒤에 HTML 삽입 후 1→11쪽까지 넘김 |
| 2. 판서 전 페이지 | 모든 페이지 종류에 필기층, 판서/조작 모드 전환, 실행 취소 | HTML 퀴즈를 풀고 → 판서로 정답 표시 → 다시 조작 가능 |
| 3. 저장·이동 | IndexedDB 자동 저장, .lessondeck 내보내기·불러오기, PWA 설치·오프라인 | 비행기 모드에서 앱 재실행 후 필기 그대로 |
| 4. 수업 다듬기 | 썸네일 드래그 재배열, 발표 모드, 빈 페이지, 성능 최적화 | 50쪽 PDF에서 페이지 넘김이 끊기지 않음, 실제 수업 1차시 시범 운영 |
| 5. 2차 기능 | PDF 내보내기, 페이지 내 HTML 위젯, 레이저 포인터 | 필기 포함 PDF가 PC에서 정상 열림 |

## 8. 리스크와 검증 항목

가장 큰 리스크는 웹 브라우저 기반 필기의 지연이다. Phase 0에서 먼저 확인한다.

| ID | 리스크 | 대응 |
| --- | --- | --- |
| R1 | 브라우저 필기 지연이 스타노트보다 큼 | `getCoalescedEvents()`·`getPredictedEvents()`로 점 보간, 획 진행 중에는 전용 캔버스에만 그리고 끝나면 합성. 그래도 부족하면 Android WebView 셸(Capacitor) + 네이티브 저지연 잉크로 전환 검토 |
| R2 | S펜 사이드 버튼·필압이 브라우저에 안 넘어옴 | Phase 0에서 `pointerType`, `pressure`, `buttons` 값 로깅으로 확인. 안 되면 툴바 버튼만으로 모드 전환 |
| R3 | HTML 웹앱 안의 터치·스와이프와 페이지 넘김 충돌 | HTML 페이지는 스와이프 넘김 끄고 가장자리 버튼만 사용 |
| R4 | HTML 파일이 외부 라이브러리(CDN)를 불러옴 | 오프라인이면 깨짐 → 삽입 시 외부 참조 감지해 경고 표시 |
| R5 | 사용자 HTML의 스크립트가 앱 데이터에 접근 | iframe `sandbox="allow-scripts allow-forms allow-popups"`, `allow-same-origin` 금지 |
| R6 | localStorage를 쓰는 기존 웹앱이 sandbox에서 오류 | URL 페이지로 삽입하도록 안내(그 앱의 원래 주소로 열림) |
| R7 | 큰 PDF에서 메모리 부족 | 현재 쪽 ±2쪽만 렌더링, 나머지는 해제 |
| R8 | 미러링 화면에서 HTML이 잘림 | 페이지별 비율(16:9, 4:3, A4) 지정 + 확대 비율 자동 맞춤 |

**Phase 0 태블릿 체크리스트**

- [ ] S펜 필압 값이 0\~1로 들어오는가
- [ ] 손바닥을 대고 써도 오인식 없는가
- [ ] 빠르게 쓴 한글 필기가 끊기지 않는가
- [ ] S펜 사이드 버튼 신호가 들어오는가
- [ ] 홈 화면에 설치한 PWA가 전체 화면으로 열리는가
